OpenHisto · Research software

Computational pathology in Python

Created and maintained by Abteen Arab

OpenHisto is a Python package for computational pathology. It provides tools for slide preparation, feature extraction, segmentation and vision-language analysis. It also supports classification, risk and survival modelling, and visual inspection through segmentation overlays and QuPath exports.

Computational pathology tasks

Modules use indexed patches, feature representations and spatial metadata for the tasks described below.

01 · PREDICTION

Classification

Binary and multiclass tasks using MIL backbones, neural heads and eleven classical classifiers.

Classification methods → 02 · TIME-TO-EVENT ANALYSIS

Risk & survival

Cox relative risk, discrete hazards and training-calibrated survival estimates with linear or MLP heads.

Survival methods → 03 · SPATIAL STRUCTURE

Segmentation

Train, evaluate and predict semantic masks, with automatic, prompted and embedding-conditioned backends.

Segmentation workflows → 04 · IMAGE AND LANGUAGE

Vision-language models

Prompt-conditioned patch descriptions using pathology vision-language models. Access requirements and verification limits are documented per profile.

VLM integrations → 05 · VISUAL INTERPRETATION

Visualization

Segmentation palettes, overlays and annotation exports. A dedicated slide and attention viewer is not currently available.

Visualization outputs → 06 · DATA AND REPRESENTATIONS

Preparation & features

Acquire slides, extract multiscale patches, normalize stain and encode pathology representations for downstream tasks.

Data formats

Representations and provenance

Patch archives and feature stores retain spatial coordinates, source identifiers and processing metadata for downstream analysis.

Workflow guide →
01

Indexed patch archives

Pixels, magnification, level-zero coordinates and valid bounds are stored in an HDF5 archive per slide.

02

Explicit model inputs

Feature bags, spatial graphs and aligned hierarchies have distinct contracts. Model access and runtime requirements are documented by profile.

03

Ordered feature storage

AnnData stores feature vectors with patch metadata. Compatible reruns reuse completed vectors and retain their source identities.
